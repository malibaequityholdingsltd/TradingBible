# 2026-10-22 — ID card print parity

## What changed
- `apps/web/src/pages/StaffIdCardsPage.jsx`
  - Added `html-to-image` (`toPng`) print baking. The hidden capture host renders each selected card at 1× (648×408), then captures it at 2× (1296×816) and puts the resulting PNG into the print portal at 324×204 CSS (true CR80).
  - Print order is now all fronts, then all backs; `Sides` still supports front/back/front+back and `Paper` still supports CR80/Letter.
  - The print sheet no longer depends on browser font substitution, `zoom`, `transform`, or “Background graphics”.
  - “Print cards” now shows “Preparing…” while capturing. Use that button — not Cmd/Ctrl+P — so the baked images are used.
  - Updated the print guide accordingly.
- `apps/api/src/routes/digest.js`: admin email domain regex changed from `tradingbible.app` to `tradingbible.app`.

## GH.pdf diagnosis
- `GH.pdf` was A4/2 pages, not CR80. It was a browser print of the preview/admin page with background graphics off and fit-to-page on; that is why the black base was missing and the card looked compressed/overlapping.
- It was not generated by the app's print portal. The new baked-image print path prevents that failure mode.

## Notes / lessons
- Do not use Swift PDFKit to extract pages from these PDFs: it corrupts the embedded card images (photos vanish, severe chroma fringing). Use the app’s `Page.printToPDF` export or a proper PDF tool.
- Supabase Auth Site URL/redirect allowlist still points at `https://tradingbible.app`; needs dashboard update to `.net`/localhost when access is available.
- No git commits made; changes are on disk only.
